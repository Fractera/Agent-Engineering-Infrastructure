# DESTINATION `database` — the automation's own records

> **Law of instructions: ENGLISH, COMPACT, one fact one home.** Its reader is a model that must read the core too, so every line here is paid on every session. Prune before you append; never restate what another instruction already says — link to it by name.

**Function:** `deliverDatabase` (derived). **Keys:** none — the store is local to the folder.

A store, not a delivery: nothing is sent anywhere, a row is kept so it can be found later. One of three
stores, and the one that answers "what exactly happened".

## What its function does

Writes a row in the shape the automation's own tables expect, and links it to whatever else this run
produced — the file in object storage, the vector document, the marker on the map.

## Every row carries its links

A record that cannot be traced to its file and its meaning is half a record. Links go BOTH ways: from the
row to the object, from the object back to the row. "No link" is not a state that exists here.

## What it must never do

- **Never store what belongs in another store.** The full text for searching belongs in vector memory, the
  bytes in object storage. This store keeps the facts and the links.
- **Never write on a question.** A question about data is not data — that boundary is enforced upstream by
  the front, and this door must not quietly re-create the record it was told not to make.
- **Never guess a shape.** If the route did not say what the row is, the row is not written.

## When to reveal it

Whenever anything must survive the run. It is the store the owner searches first.
