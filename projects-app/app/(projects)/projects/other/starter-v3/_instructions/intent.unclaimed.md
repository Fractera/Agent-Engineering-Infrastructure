# CLASS `unclaimed` — nobody recognized it, and that is said out loud

> **Law of instructions: ENGLISH, COMPACT, one fact one home.** Its reader is a model that must read the core too, so every line here is paid on every session. Prune before you append; never restate what another instruction already says — link to it by name.

**Where the answer lives:** nowhere yet. **Routes to:** an output — an honest sentence.

The last node of the layer. If no class claimed the run, this one does, and the automation says it did not
understand.

## Why this is not a placeholder but the conscience of the layer

A front without it always has a silent default — the widest class quietly absorbs everything unrecognized,
and the owner sees a confident wrong action instead of a question. That is exactly how v2 behaved: when the
model failed, the classifier degraded silently into «save», and a failed classification looked like a
successful note.

This class closes the set of outcomes. With it, «the run went somewhere unexplained» stops being possible:
either a class claimed it and the journal names the class, or this one claimed it and the human was told.

## How it recognizes

By exclusion only: it claims when `intentClass` is still empty. It contains no forms of its own and must
never grow any — a backstop that starts recognizing things is no longer a backstop.

## What it must never do

- **Never apologize at length or offer a menu of everything.** One sentence: not recognized, and the two or
  three things the automation does understand.
- **Never write anything.** An unrecognized request produces no record.
- **Never be moved from last position.** Standing anywhere but last, it swallows the layer.

## Reuse

Domain-neutral, and mandatory. An automation without this class has a hidden default, whether or not
anybody meant to give it one.
