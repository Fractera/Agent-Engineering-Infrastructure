# Поисковая оптимизация: что уже построено

Ниже — не список намерений, а перечень того, что стоит в вашем проекте и работает
на каждой странице. Читать целиком не обязательно: если коротко, поисковая часть
готова, и трогать её не нужно.

## 1. Страницы отдаются готовым HTML

Каждая публичная страница **собирается заранее** и приезжает к посетителю целым
документом. Не «пустая страница, которая дособерёт себя в браузере», а текст,
который виден сразу — в том числе при выключенном JavaScript.

Это и есть та часть, которую в проектах, написанных с помощью ИИ, теряют чаще
всего: страницы незаметно становятся динамическими, каждый заход начинает считать
их заново, сервер держит нагрузку, а поисковик видит медленный ответ. Здесь на это
стоит прямой запрет уровня архитектуры, а страницы обновляются по расписанию
(ISR): содержимое свежее, а работы на запрос по-прежнему ноль.

Что это даёт по деньгам: рост посещаемости **не увеличивает счёт за сервер**.
Отдать готовый файл стоит примерно столько же и на сотне визитов, и на сотне
тысяч.

## 2. Метатеги собирает один механизм

Заголовок, описание, ключевые слова, автор, канонический адрес, карточка для
соцсетей (OpenGraph), карточка для X/Twitter, разрешение на индексацию,
подтверждения Google и Yandex — всё это строит **один** сборщик из ваших настроек.

Почему это важнее, чем кажется: набор метатегов, написанный руками на каждой
странице, покрывает те поля, о которых вспомнили. Через полгода половина страниц
отдаёт в соцсети чужую картинку и описание сайта вместо описания страницы.

Описание автоматически укорачивается до 160 символов — длиннее поисковик всё
равно обрежет, и обрежет посреди слова.

## 3. Языковые сигналы

- `<html lang="…">` — на каждой странице свой, по её языку. Это то, из чего
  экранный диктор понимает, как читать, а поисковик — на каком языке страница.
- **Канонический адрес** — у каждой страницы свой собственный.
- **`hreflang`** — перечень переводов страницы, включая `x-default` для
  посетителя, чей язык вам не подходит.
- Пять значений (имя, описание, шаблон заголовка, ключевые слова, имя сайта)
  читаются **на языке страницы**, а не одним набором на весь сайт.

Ошибка, которую эти три строки предотвращают, стоит дороже всего в
многоязычном проекте: без них поисковик считает переводы **копиями друг друга**,
выбирает одну версию и остальные в выдачу не пускает. Проект работает, страницы
открываются, а половины языков в поиске просто нет.

## 4. Структурированные данные (JSON-LD)

Проект отдаёт поисковику машинное описание себя:

| Что описывается | Тип |
|---|---|
| Сайт | `WebSite` |
| Организация | `Organization` (+ контакты) |
| Локальный бизнес | `LocalBusiness` (+ адрес, координаты) |
| Хлебные крошки | `BreadcrumbList` |
| Вопросы и ответы | `FAQPage` |
| Товар | `Product` + `Offer` (цена, наличие) |
| Новость / статья / документ | `NewsArticle` / `BlogPosting` / `TechArticle` |

У статьи при этом указываются автор (как **личность**, со ссылками на его
профили), издатель с логотипом, даты и адрес самой страницы. Именно из этого
вырастают расширенные результаты в выдаче — звёзды, цены, раскрытые вопросы.

## 5. Карта сайта и robots

- `sitemap.xml` — страницы, множество которых конечно.
- Товары — **в отдельных картах по частям**: в одном файле их не больше 50 000,
  и при превышении поисковик отбрасывает файл целиком, вместе со страницами.
  Этой ловушкой заканчивается почти каждый растущий каталог.
- `robots.txt` — собирается из ваших настроек и объявляет все карты сразу.

## 6. Ссылки внутри статей проверяет машина

У материалов два вида ссылок: внешние — всегда с полным адресом, открываются в
новой вкладке, чужие домены получают `nofollow`; внутренняя — на главную на языке
этой же статьи. Правила проверяет команда `npm run check:content`, и материал с
нарушением просто не проходит.

## Что остаётся вам

Заполнить настройки приложения: имя, описание, адрес сайта, картинку для соцсетей,
иконки. Всё остальное перечисленное включится само.
